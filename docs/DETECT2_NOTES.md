# 球体识别重做说明

## 接入方式（已生效）

`detect.py` 现在是**新引擎的接口层**：对外保留旧的全部公开接口
（`analyze_frame` / `detect_felt` / `draw_detection_preview` / `get_cloth_name` /
`TableState` / `Ball`），内部调用 `detect2.py`。
因此 `analyze.py` / `overlay.py` / `main.py` **无需任何改动**即可使用新引擎。

```
analyze.py / overlay.py / main.py
        |
        v
   detect.py        <- 接口层：坐标变换、袋口归一化、球心夹取
        |
        v
   detect2.py       <- 引擎：Lab 局部背景 + 双通道物理证据
```

旧的 HSV 阈值实现保留为 `detect_legacy.py`（仅供 `bench.py` 做基线对比，
不参与运行时）。

### 坐标系约定（关键）

`TableState.felt_rect` = **可放球的比赛区**（由实测袋心反推），不是绿色台呢外框。

* 四角即四个角袋中心，与 `geometry.default_pockets()` 一致；
* `Ball.x/y` 相对 `felt_rect` 原点 → `felt_x + ball.x` 得图像坐标，
  `ball.x / felt_w` 得归一化坐标；
* 归一化后球心恒落在 `[rx, 1-rx]`（长边）/ `[ry, 1-ry]`（短边），
  贴库球恰好等于边界值，满足 `geometry` 的库边镜面 `y = r` 前提。

实测由袋心反推的比赛区在短边方向偏大约 **3px**（袋心略在台呢内沿外侧），
于是贴库球会「越界」。**不内缩 `felt_rect`**（会连带把贴库球裁出检测范围，
实测丢球），改为在 `detect.py` 输出时**只夹球心**：
检测范围不变，仅把输出坐标夹进合法区间，夹取量 ≤3px
（相对短边 0.5%，对瞄准角影响 <0.3°）。

> 注：这个越界在**旧实现里同样存在且更严重**（旧 6.5px，新 3.3px），
> 属既有的坐标建模误差，非本次回归。夹取后 12/12 帧全部合规。

### 半径标定

匹配滤波扫描给出的半径有偏差。半径不准会歪掉幽灵球位置、
库边内移量与走廊宽度，故必须校正。

`config.BALL_RADIUS_SCALE` / `BALL_CENTER_BIAS_X/Y` 是**旧引擎**（detect_legacy）
的补偿项，新引擎不使用。新引擎的修正是
`config.BALL_RADIUS_FIX_SCALE = 0.8816`（见下），
`BALL_RADIUS_PX`（强制半径）仍然生效。

**最终标定（已获用户确认）**：改用**边缘点稳健圆拟合**同时求圆心与半径，
再乘修正系数 `0.8816`，实测 `r/短边 = 0.02586`。
三路独立证据互相印证 + 5 样本离散度 ±0.9%。
> 为什么放弃距离变换：等式「球心处 dt = 球半径」只在**球是孤立圆盘**时成立；
> 贴库球的掩码会与库边连成一片，实测半径被高估约 13%。
> 详见 [done.md](done.md) 一之六。

## 为什么要重做

旧 `detect.py` 对 8 种颜色**分别做 HSV 阈值切分**，病根有三个：

1. **阈值与台呢皮肤、光照强耦合** —— 换皮肤或换光照即崩；
2. **同色球直接消失** —— 绿球在绿台呢上、红球在红台呢上，掩码切不出来；
3. **球贴球时连通域合并** —— 一堆红球粘在一起只能算出一颗；
   且半径靠外接矩形估，阴影/高光把质心拉偏。

## 新思路：不按颜色切，用「物理证据」判球

核心转变：**不再问「这个像素是什么颜色」，而是问「这里是不是一个球」。**

球有两个与颜色无关的物理特征：

| 特征 | 球 | 台呢 |
|------|-----|------|
| **明暗渐变**（Vstd） | 球体必有高光/渐变，实测 **25~85** | 平坦，**≈0.4** |
| **盘内色差覆盖率** | 实心圆盘，**88.8~100%** 偏离台呢 | 库边只切过盘一侧，**43.6~75.4%** |

流水线：

```
1. find_felt        定位绿色台呢矩形
2. response_map     Lab 空间估计局部台呢背景 → 感知色差图 d
3. detect_pocket_centers  实测六袋中心（不假设在矩形角上）
   play_rect_from_pockets 由袋心反推比赛区
4. estimate_radius  粗到精扫描统一球半径（1/4 分辨率粗扫 + 全分辨率精修）
5. 双通道峰生成
     · 色彩通道 col  = 圆盘均值 − 环形均值（环形只统计台呢样像素，贴库球稳健）
     · 明暗通道 vstd = 球盘内 HSV-V 标准差
6. 双重门限裁决
     门限一：disk_fill_ratio ≥ 0.85   （实心圆盘证据，**主判据**）
     门限二：色差 > 20 **或** Vstd > 12，且置信度 ≥ 0.55（兜底证据）
7. 颜色分类：内盘中位 Lab 对参考调色板最近邻
8. 半径标定：边缘点稳健圆拟合 + `BALL_RADIUS_FIX_SCALE` 修正
9. 剔除：NMS + 边界/袋口
```

### 关键设计点

- **`disk_fill_ratio` 是主判据**。球是实心圆盘，整个盘都偏离台呢（88.8~100%）；
  库边是长条只从盘一侧切过（43.6~75.4%），高光是球面上一小块。
- **兜底证据用「或」而不是「与」**。球偏离台呢只有两种成因：
  A 颜色不同（绝大多数球）、B 明暗渐变（与台呢同色的绿球）。
  真实游戏球两个特征都强（色差 88~120、Vstd 34~58），所以 AND 在真实截图上
  看似正常；但合成 demo 是纯色填充球（色差 101~150、Vstd 0~12），
  AND 会把它们全部误杀。实测 OR 在真实帧 19/19、合成 5/5 全部正确。
- **置信度门限排除台呢水印**。台呢上「腾讯桌球」水印的弧形亮线穿过球盘时，
  覆盖率能勉强过 0.85，但颜色与台呢接近、明暗渐变也弱，两个裕度都小。
  实测该误检 `conf=0.43`，而全部真球 `conf=0.90~0.99`，故设门限 0.55。
- **Vstd 是唯一能发现同色球的通道**。绿球在色彩通道上色差仅 26.6，
  与台呢同色，根本无法形成尖峰；但它的 Vstd 是 32.8，与台呢差 80 倍。
- **环形均值只统计台呢样像素**（权重 `exp(-d/tau)`）。
  朴素写法 `mean(disk) - mean(annulus)` 对贴库球失效：
  环形区含库边，把环形均值抬高，真绿球得分被压到 18.9（真球 57~81）→ 漏检。
- **半径由数据自身估计，不写死**。最终经边缘点圆拟合标定为 17.43px
  （1286x674 台面），即 `r/短边 = 0.02586`。

## 已知限制

- **速度**：约 1.2s/次。半径扫描占大头；若需更快可缓存上一帧半径
  （球台不变时半径恒定），或把粗扫降到 1/8 分辨率。
- **绿球置信度偏低**（0.57）：因为它与台呢同色，分类裕度天然小。
  位置与判定正确，只是置信度数值低，属预期。
- **比赛区短边偏大 ~3px**：见上文坐标系说明，已用球心夹取消除影响；
  根因（袋心略在台呢内沿外侧）未彻底修正，因为它不影响瞄准精度。
- **红球数**：当前局面 14 红（非满台 15 红），是实际球局状态，非漏检。
  已用色相带全台扫描确认：台面无黄球、无粉球。
- 依赖绿色台呢定位（`find_felt` 色相窗 40~88）。若台呢换成蓝/红/紫，
  需相应调整 `find_felt` 的色相范围。
