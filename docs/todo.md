### 0. 游戏的物理与真实斯诺克不同（影响所有几何假设）
- **实测**：台面宽度约为 **36.9 个球直径**，而真实斯诺克是 **68.0**
  —— 游戏的球相对台面约为真实的 **1.84 倍**。
  （注：早前记为 32.5，那是因为当时球半径被高估了约 13%；
   半径修正后 `台宽/球直径 = 1286/34.86 = 36.9`，
   等价于 `1/(2*0.02586) ≈ 19.3` 的直径/短边比的换算。）
- **含义**：`geometry.py` 里那些源自真实斯诺克的经验参数
  （进球角 110°、中袋 15° 夹角、袋口余量等）**未必适用于本游戏**，
  它们是按真实台子比例设的。库边反弹是否真是理想镜面，也**未经实测**。
- **进展**：库边**坐标系**已用游戏自绘图元独立验证
  （见 done.md 一之四，偏差仅 0.47px → 镜面**位置**假设成立）。
  剩下未验证的是**反弹角规律**（入射角是否等于反射角）。
- **建议**：用球的运动轨迹实测反弹规律，测入射/出射角之比，
  若显著偏离 1 则引入 `CUSHION_REBOUND_SCALE`。
  `dev/measure_rebound.py` 已备好，但它需要**运动中的球**，
  而实测合成鼠标/键盘输入不被游戏响应（Chrome 渲染），
  所以必须**真人击球**配合：
  1. 我启动连拍（`python dev/measure_rebound.py 60`）；
  2. 你在连拍期间击球让球撞库；
  3. 脚本自动找方向突变点、算出入射/反射角之差。
- **注**：这是**测量优先于假设**的方向，比继续抠像素精度更有价值。

### 1. 悬浮窗与游戏窗口的坐标系对齐
- **位置**：`src/overlay.py` `_sync_to_game()` / `_tick()`
- **问题**：overlay 用 `find_window_rect()` 的**窗口矩形**（含标题栏与边框）定位自身，
  而标注用 `felt_rect` 在**截图**像素坐标绘制。当 DPI 缩放不为 100%、
  或窗口有边框/阴影时，二者会整体偏移若干像素，导致线与球对不齐。
- **实测线索**：本次实测窗口 `1588x959 @(486,215)` 与截图尺寸一致（DPI 100%），
  故当前环境看不出问题；非 100% 缩放时才会暴露。
- **建议**：
  1. 统一用「客户区（client area）原点」：`GetClientRect` + `ClientToScreen`；
  2. 或在绘制时按 `截图尺寸 / 窗口尺寸` 做一次线性缩放校正；
  3. 加一个 F7 校准时的对齐自检（画十字标记，人工确认）。
- **验证方式**：把球摆在台面四角，看 overlay 圈是否与游戏球重合。

### 2. 仅支持绿色台呢定位
- **位置**：`src/detect2.py` `find_felt(hue_lo=40, hue_hi=88)`
- **问题**：新识别引擎的台面定位写死了绿色色相窗。旧实现有
  `FELT_CLOTH_MODE=auto`（绿/蓝/红/紫/黄自动选主色），**该能力在新引擎里丢失了**。
- **影响**：换皮肤（蓝/红/紫台）后 `find_felt` 直接失败 → 识别不可用。
- **建议**：把旧实现的「按大矩形评分选台泥主色」逻辑移植到 `detect2.find_felt`；
  或至少把色相窗做成 `config` 可配 + 多候选回退。
- **注意**：红色台呢与红球同色，即便定位成功，红球识别仍需额外手段（见 P2-9）。

### 3. 绿球（green）球心偏差 —— 当前最值得做的识别改进
- **现象**：用户反馈「绿球歪了」。实测其圆心与独立估计相差约 **4.5px**
  （红球仅 ~1px），是全部球里最差的一个。
- **根因（已定量确认）**：绿球的**色相与台呢完全重合** ——
  实测其邻域的「非台呢」掩码几乎**全为空**，即颜色判据**看不见绿球**；
  它只能靠明暗纹理（Vstd）识别，而高光/阴影会把质心拉偏。
- **已确认与半径无关**：半径修正已获用户确认（done.md 一之六），
  所以这是**球心定位**的问题，不是尺度问题。
- **建议（按把握排序）**：
  1. **把球心精修换成「边缘点圆拟合」**（最有把握）：
     即 done.md 一之六标定半径时用的方法，它**基于 Lab 亮度距离而非色相**，
     因此对绿球同样有效；且同时解出圆心与半径，从根上避免质心偏移。
     可直接复用 `dev/fit_ball_circles.py` 的 `robust_fit()` 逻辑。
  2. 对低置信度球（绿球 conf≈0.85）**用更多角度**做边缘采样，
     提高信噪比。
  3. 若仍不稳，在 overlay 里**允许用户点选/微调**目标球（见 P1-6）。
- **验收方式**：用「边缘点圆拟合」的圆心作为参照，
  断言绿球偏移 < 1.5px（与红球同级）。

### 3b. 其他颜色识别风险（已基本解决）
- **现状**：8 色分类已相当稳（实测 12 帧 + 满台 22 颗零错误）。
- 已修复一类真实误检：白球被瞄准辅助圈染色 → 误判粉球
  （见 done.md 精度专项）。
- **建议**：在 status 里显示低置信度球，提示用户复核。

## P1 — 实操体验

### 4. 单次分析耗时约 2.1s（预算 8s，余量充足）
- **构成**：多帧融合识别（默认 5 帧 ≈ 2.1s）+ 几何约 1.1s
- **现状**：时间预算放宽后已做两件事——
  1. 半径扫描恢复为**全分辨率 + 子像素插值**（早前为压时间用 1/4 分辨率粗扫）；
  2. 新增**多帧时域融合**，剔除瞬时伪检并平滑球心。
- **可调**：`config.FUSION_FRAMES`
  - 1 = 关闭融合（约 1.2s，退回旧行为）
  - 3 = 1.6s（已足以剔除 1~2 帧的瞬时伪检）
  - 5 = 2.1s（**默认**）
  - 12 = 3.7s（收益递减）
- **几何侧**：`find_pot_paths` 对「每目标 × 每袋 × 多库序列 × 每颗 B 传球」组合
  - **建议**：先只搜当前目标球；传球限制 B 为最近 3–4 颗；库序列先 1 库再 2 库。

### 4b. 融合对「持续性错误」无效
- **实测边界**（受控注入实验，5 帧 / min_votes=3）：
  假球出现 1~2 帧 → 被剔除；出现 ≥3 帧 → 漏过。
- **含义**：融合能治「偶发干扰」（球杆扫过、瞄准圈闪烁），
  治不了「每帧都在的错误」（稳定的 UI 图元、常驻特效）。
  后者必须靠单帧判据（`disk_fill_ratio` / 证据门）解决。
- **若要更强**：提高 `FUSION_FRAMES`（min_votes 随之提高），代价是耗时线性增长。

### 5. 无「锁定上一帧球局、只改目标重算」
- **位置**：`src/overlay.py` `on_cycle_target()`（当前只改颜色，注释里也写明
  「下次 F8/F9 生效」）
- **建议**：缓存最近一次 `img`，F10 后直接 `analyze(cached_img)` 重算并重绘，
  避免每次换目标都要重新截图。

### 6. 鼠标穿透后无法点击悬浮窗
- **现状**：靠热键操作；热键被占用时难处理
- **建议**：加一个不穿透的小控制条，或托盘图标；或实现「点选目标球」（见 P0-3）

### 7. 无实时自动分析
- **现状**：仅 F8/F9 手动触发
- **建议**：可选「每 0.5s 自动分析」，需注意 CPU 占用与游戏焦点；
  实现前先做 P1-4 的提速，否则 2.2s/次跟不上。

## 本轮已确认并获得用户认可

用户反馈：**「现在球体检测很准确」**。以下为确认范围内的能力，
均已加回归测试护栏：

| 能力 | 关键值 | 护栏 |
|---|---|---|
| 球半径标定 | `BALL_RADIUS_FIX_SCALE = 0.8816`，`r/短边 = 0.02586` | `tests/test_detect.py`（228 断言） |
| 白球检出 | 修复多帧融合的半径复用语义 bug | `tests/test_fusion_cue.py`（22 断言） |
| 中袋瞄准点 | 取长边中点 `(0.5, 0/1)` | `tests/test_pockets.py`（51 断言） |
| 几何与镜面 | 库边坐标系偏差 0.47px | `tests/test_geometry.py` |
| 多帧时域融合 | 默认 5 帧 ≈ 2.1s，剔除偶发伪检 | `dev/verify_fusion_value.py` |

**下一个最值得做的识别改进**：绿球球心（见 P0-3）。
