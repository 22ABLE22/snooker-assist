## 一、球体识别 v2（最近一次重大重做）

旧实现对 8 种颜色分别做 HSV 阈值切分，病根是阈值与台呢皮肤/光照强耦合、
同色球（绿球在绿台呢上）直接消失、球贴球时连通域粘连成一团。

**新方案改用与颜色无关的物理证据判球：**

- [x] **Lab 局部背景建模**：降采样中值估计台呢背景 → 感知色差图（抗光照/皮肤变化）
- [x] **双通道峰生成**
  - 色彩通道：圆盘−环形匹配滤波，**环形只统计台呢样像素**（贴库球不再被库边压制）
  - 明暗通道（Vstd）：球体必有高光渐变，是**唯一能发现同色球**的通道
- [x] **`disk_fill_ratio` 主判据**：球是实心圆盘（覆盖率 88.8~100%），
      库边只切过一侧（43.6~75.4%）→ 彻底排除库边/高光/球杆
- [x] **证据门（色差 OR Vstd）+ 置信度门限**：兼顾真实球与合成纯色球，
      排除台呢「腾讯桌球」水印弧线（误检 conf=0.43 vs 真球 0.90~0.99）
- [x] **实测袋心定位六袋** + 由袋心反推比赛区（不假设袋在矩形角上）
- [x] **半径两步标定**：匹配滤波粗估 → 距离变换精修（阈值经弦长法标定，误差 ≤0.02px）
- [x] **帧间零抖动**：12 帧离线 + 实时连续抓取，球数/半径/颜色分布完全一致
- [x] **接口层兼容**：`detect.py` 保留旧的全部公开接口，`analyze/overlay/main` 零改动
- [x] 实测**满台局面**（22 颗：15 红 + 6 彩 + 白）比旧实现多找回 1 颗贴库红球

## 一之二、精度专项修复（时间预算放宽到 8s 后）

- [x] **袋口定位**：原来只在裁剪图内部搜袋洞，袋洞被窗口边界切掉一部分，
      质心被系统性拉向台面内侧（角袋偏内 33px、中袋 19px）。
      改为在**整图**上围绕比赛区搜索，并让中袋保留实测 y（不再硬写 0/1）。
      **结果：六袋偏差全部降到 0.1~0.2px**（提升约 160 倍）。
- [x] **粉球误检修复**：游戏在瞄准态给白球画灰色辅助圈，圈压在球体上；
      颜色采样半径 0.62r 会把圈像素混进来，中位 Lab 被拉向灰色 →
      白球被判成粉球（conf 0.36）。改用 0.30r 小盘采样后判定正确（conf 0.99），
      且实测全部真实球在两种采样下判定一致，绿球置信度反而更高（0.85 vs 0.62）。
- [x] **半径校正与袋口排除的顺序 bug**：排除半径 = 2.2×r，但原先在半径校正
      **之前**执行，用的是偏小的扫描值 r_est，导致排除圈偏小、
      袋洞可能被当成黑球留下。已改为先校正半径再排除。
- [x] **恢复全分辨率半径扫描 + 子像素抛物线插值**：早前为压时间用过
      1/4 分辨率粗扫，峰值位置会因缩放偏移、可能选错候选。
      现改为全分辨率逐半径扫描 + 峰值抛物线插值，耗时约 1.1s（预算 8s）。

### 精度实测数据

| 指标 | 修复前 | 修复后 |
|------|--------|--------|
| 角袋定位偏差 | 33 px（≈1.7 球半径） | **0.1~0.2 px** |
| 中袋定位偏差 | 19 px（≈1 球半径） | **0.1~0.2 px** |
| 粉球误检 | 满台局面出现 2 颗（其一为白球） | **1 颗，正确** |
| 球心精度（合成真值） | — | **中位 0.45px，max 1.26px**（2.3% / 6.4% 球半径） |
| 单次耗时 | 0.6s | **1.1s**（预算 8s） |
| 实时连续 5 帧 | — | 22 颗 / r=19.772 / 颜色分布**完全一致** |

> 关于袋口修复的实际收益：虽然角袋偏差从 33px 降到 0.2px，
> 但逐球逐袋实测对**最终瞄准角**的影响是中位 0.009°、最大 0.509°
> （144 组样本，无一超过 1°）。这是因为幽灵球算法里袋口在分母、
> 且目标球离袋越近影响越小。修正仍有价值（视觉上袋口圈准确、
> 边界情形更稳），但不应夸大其对命中率的贡献。

## 一之三、多帧时域融合（架构性改进）

原架构是**开环**的：一次截图 → 一次判断。两个结构性弱点：
单帧噪声无法抑制（球心 ~0.5px 抖动没人去平），瞬时干扰无法排除
（球杆扫过、瞄准圈、特效只在个别帧出现）。

时间预算 8s / 单帧约 1.1s，有充足余量做多次观测。

- [x] **`src/fusion.py`**：多帧结果按位置聚类投票
  - 并查集聚类（同帧内不合并，NMS 已保证同帧不重复）
  - **≥60% 帧命中才算球** → 剔除瞬时伪检
  - 球心按置信度加权平均 → 噪声按 √N 衰减
  - 附带 `votes` / `spread` 诊断字段
- [x] **`detect.analyze_frames()`**：产品级多帧入口
- [x] **半径复用**：第 1 帧完整识别拿半径，后续帧复用（半径是渲染属性、跨帧恒定）
      → 单帧耗时 **1.1s → 0.26s**（4.2 倍）
- [x] **接入 overlay**：`config.FUSION_FRAMES`（默认 5）控制连拍帧数，
      状态栏显示「融合N帧」；设为 1 即退回旧行为
- [x] **接入 analyze**：`extra_frames` 参数（可选，零侵入）

### 融合的因果验证（受控实验）

真实数据无法稳定复现瞬时伪检，故用受控实验：在真实帧上人为叠加「假球」。

配置 `FUSION_FRAMES=5`（min_votes=3）：

| 假球出现帧数 | 单帧识别 | 融合后 | 真球保留 |
|---|---|---|---|
| 1 | 20 颗（无从分辨真假） | **19 颗，假球被剔除** | 19/19 |
| 2 | 20 颗 | **19 颗，假球被剔除** | 19/19 |
| 3 | 20 颗 | 20 颗，假球漏过 | 19/19 |
| 4 | 20 颗 | 20 颗，假球漏过 | 19/19 |
| 5 | 20 颗 | 20 颗，假球漏过 | 19/19 |

**价值与边界都清楚了**：融合对「偶发/瞬时」干扰有效（1~2 帧内出现必被剔除），
对「持续存在」的错误无效（≥3 帧就留得住）——后者仍需靠单帧判据解决。

### 耗时（预算 8s）

| 帧数 | 耗时 | 说明 |
|------|------|------|
| 1 | 1.21s | 关闭融合（旧行为） |
| 3 | 1.61s | 已足以剔除瞬时伪检 |
| 5 | 2.06s | **默认**，余量充足 |
| 7 | 2.46s | 更稳的投票 |
| 12 | 3.69s | 收益递减 |

### 系统性的量化发现（顺带确认）

- **游戏的球相对台面约为真实斯诺克的 2 倍**：台面宽度只有 32.5 个球直径，
  而真实斯诺克是 68.0。说明游戏用自己的简化物理，**不能套用真实斯诺克参数**
  （这一条此前被默认忽略了）。
- **样本局限**：现有 12 帧是同一球局，逐帧离散度实测为 0.000px，
  说明它们几乎完全相同（仅 UI 计时器不同）。因此「12 帧零波动」只证明了
  **确定性**，不能证明鲁棒性 —— 真实鲁棒性证据来自上面的受控注入实验。

## 一之四、利用游戏自绘图元做独立验证（新信息源）

**此前完全没被利用的信息源**：游戏在瞄准时会自己画
「白球路径线 + 空心指示环」。这是**游戏自身物理引擎的输出**，
比从像素统计里推断任何量都权威。

- [x] **确认可稳定提取**：台面内近白像素 → 按「近正方 + 低填充 + 尺寸≈球直径」
      筛出空心环 → 最小二乘圆拟合
- [x] **判定环的图元身份**（两个候选假设的可证伪检验）：
  - H1「白球贴库时的球心位置」：到最近 `play_rect` 边距离应 == r
    → **实测 0.976r，成立**
  - H2「幽灵球位置」：到某目标球距离应 == 2r → 实测 4.60r，**排除**
- [x] **独立验证了 geometry 的库边坐标系**（此前无法验证）：
  反推库边面 = 环心 − r = **148.53px**，而 `play_rect` 左边界 = **149px**
  → **偏差仅 0.47px（2.4% 球半径）**
- [x] **据此否证了我先前的一个怀疑**：我曾多次怀疑 `play_rect` 比真实库边
      偏外 0.24~0.77 球半径（并据此提过修正方案）；用游戏自己的图元验证后
      结论是 —— **不偏，镜面假设成立**。先前那些"偏差"来自像素扫描
      误采了库边上的绿色高光/装饰，不是真实几何偏差。

### 关键负面结论：合成鼠标输入不被游戏响应

为让脚本自动采集**多个瞄准方向**的样本，尝试了合成鼠标输入
（`SetCursorPos` + `SetForegroundWindow`）。实测：

| 检查 | 结果 |
|------|------|
| 游戏窗口是否前台 | 是 |
| 是否最小化 / 可见 / 被禁用 | 否 / 是 / 否 |
| 窗口中心点归属 | 确为游戏窗口 |
| 移动鼠标后画面变化 | **0.01%**（几乎为零，仅 UI 计时器） |

**结论**：游戏（微信小程序，Chrome 渲染）**不响应合成鼠标移动**，
无法脚本化改变瞄准方向。因此：

* 本节验证只有 **1 个有效方向**（画面静止，3 帧实为同一重复）；
* 要覆盖四个方向，需**真人**改变瞄向后各截一帧，再跑
  `dev/verify_cushion_via_ring.py`；
* 同理，「实测库边反弹规律」（`dev/measure_rebound.py`）也必须
  **真人击球**才能采到运动样本。

> 这条负面结论本身有价值：它划定了自动化测试的边界，
> 避免后续再在「脚本控制游戏」上白费力气。

## 一之五、修复「检测不到白球」（半径复用语义 bug）

**现象**：白球贴左库时，界面报「未检测到白球」；单帧 `analyze_frame` 却能检出。

**根因**（上一轮引入的回归）：`analyze_frames` 做半径复用时，
把**半径校正后**的值当作 `analyze_frame2(exp_r=...)` 的初值回传。
两个量的语义不同：

| 量 | 含义 | 本帧实测值 |
|---|---|---|
| `exp_r` | 半径**扫描的初值** | 21.49 |
| 球对象的 `r` | 校正后的**最终值** | 24.77 |

尺度不匹配会让**贴库球漏检**（实测：`exp_r=None` 得 21 颗含白球，
`exp_r=24.77` 只得 20 颗、白球丢失）。后果链：

```
帧0 自动扫描 -> 有白球
帧1~4 复用 r_final -> 白球漏检
  -> 融合投票：白球仅 1 票 < min_votes=3
  -> 白球被整体剔除 -> 界面「未检测到白球」
```

**修复**：改为回传 `debug["exp_r"]`（扫描选中值）而非球对象的 `r`。

**新增回归测试** `tests/test_fusion_cue.py`（22 项断言）：
* 用 `r_scan` 与 `r_final` 分别作 `exp_r`，断言前者与单帧等价；
* 同一帧重复 5 次构成静止球局，断言融合前后球数与白球**完全一致**；
* 带噪声多帧，断言白球不丢。

该测试在 `diag_now.png`（白球贴库）与 `full_rack.png` 上都能复现原 bug，
可有效防止再次退化。

### 一次被我自己否证的误判（诚实记录）

排查过程中我发现引擎半径（24.77）远大于我用「弦长法」量到的值（17.25），
一度判断为「半径系统性高估 41%」并改写了半径校正算法。**这个判断是错的**：

* 引擎半径在两个窗口下**精确等比**：
  `19.772 × (1611/1286) = 24.769`（差 0.000），两个窗口的 `r/台面高`
  都是 `0.02934`（差 0.04%）。若是错的，不可能如此一致。
* 我的「弦长法」用 `V > 170` 只抓到了球的**亮核**。球是 3D 渲染
  （中心亮、边缘暗），阈值放宽到 `V > 120` 时外径增长并收敛：
  `17.25 → 20.25`，且不同分辨率的 `r/台面高` 一致性反而**变差**
  （0.04% → 1.52%）。
* 结论：**引擎半径是对的，我的测量方法错了**。
  已用 `git checkout` 完整回退该改动，未进入提交。

教训：改动前先用「跨分辨率一致性」这类**不依赖真值的自洽检验**判断，
而不是只拿一个阈值化的测量当真值。

```powershell
python tests\test_detect.py                # 识别回归（216 项断言）
python dev\verify_integration.py           # 识别全链路验证
python dev\live_stability.py               # 实时稳定性（需游戏窗口可见）
```

| 热键 | 作用 |
|------|------|
| F6 | 清除台面锁定（恢复自动检测） |
| F7 | 校准台面并锁定（拖边/按钮） |
| F8 | 截图分析（优先进球，其次解球） |
| F9 | 只分析进球 |
| F10 | 切换目标球颜色 |
| F11 | 显示/隐藏标注 |
| Esc | 退出 |

## 架构

```text
src/
  config.py      全部可调参数（含目录常量）
  capture.py     截屏 / 找窗口
  detect2.py     识别引擎（Lab 局部背景 + 双通道物理证据）
  detect.py      识别接口层（对外保留旧接口，内部调用 detect2）
  geometry.py    镜面、走廊挡球、进球/解球搜索与评分
  analyze.py     分析管线 + 标注绘制
  overlay.py     置顶悬浮窗 + 热键
  main.py        CLI 入口
  hotkey.py      兼容入口（转发 overlay）
tests/
  test_geometry.py             几何与规则单测
  test_detect.py               识别回归（12 帧样本，216 项断言）
dev/
  bench.py / deliver.py        新旧评测、批量交付
  detect_legacy.py             旧 HSV 实现（基线）
  verify_*.py / live_stability.py / compare_*.py
  calib_*.py / measure_*.py    标定与测量脚本
tools/
  check_mirror.py              镜面几何独立核查
docs/
  DETECT2_NOTES.md             识别重做说明（思路/标定/实测）
  history/                     历史邮件等原始材料
samples/
  recognize_12frames/          12 帧真实样本 + 识别结果 + 打分表
  evidence/                    关键证据图（满台 22 颗、找回的贴库球等）
```
